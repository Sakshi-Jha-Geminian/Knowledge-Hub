# Log Monitoring

## Introduction

Every application, service, operating system, database, and network device generates logs.

Logs provide a detailed record of events that occur within a system and are one of the most valuable sources of operational information.

When incidents occur, logs often contain the evidence needed to understand:

* What happened?
* When did it happen?
* Where did it happen?
* Why did it happen?

Log Monitoring is the practice of collecting, storing, analyzing, and monitoring logs to detect issues, troubleshoot problems, improve observability, and maintain system reliability.

Logs are one of the three pillars of observability:

```text
Metrics
Logs
Traces
```

Together, these provide comprehensive visibility into system behavior.

# What are Logs?

## Definition

A log is a time-stamped record of an event generated by a system, application, service, or device.

Logs capture activities such as:

* User Actions
* Application Events
* Errors
* Warnings
* System Changes
* Security Events

Example:

```text
2026-08-01 10:15:30
INFO
User Login Successful
UserID=12345
```

Logs help engineers understand what happened inside a system.

---

# Why Log Monitoring Matters

Consider an application failure.

Monitoring might show:

```text
Application Availability = Down
```

Metrics may show:

```text
CPU = Normal
Memory = Normal
```

Logs reveal:

```text
Database Authentication Failed
```

Without logs, identifying the root cause becomes much harder.

# Log Levels

Log levels indicate event severity.

---

## DEBUG

Detailed troubleshooting information.

Example:

```text
Variable Value = 123
```

Used primarily during development.

---

## INFO

Normal operational information.

Example:

```text
Application Started Successfully
```

---

## WARN

Potential issues that require attention.

Example:

```text
Memory Usage Reached 80%
```

---

## ERROR

An operation failed.

Example:

```text
Database Connection Failed
```

---

## FATAL / CRITICAL

Severe issues requiring immediate action.

Example:

```text
Application Terminated Unexpectedly
```

---

# Structured vs Unstructured Logs

---

## Unstructured Logs

Traditional text-based logs.

Example:

```text
User login failed due to invalid password
```

Difficult to search consistently.

---

## Structured Logs

Logs stored in a machine-readable format.

Example:

```json
{
  "timestamp":"2026-08-01T10:15:30",
  "level":"ERROR",
  "service":"payment-service",
  "message":"Database connection failed"
}
```

Benefits:

* Easier Searching
* Better Analytics
* Faster Correlation

# Centralized Logging

## What is Centralized Logging?

Centralized logging stores logs from multiple systems in a single location.

Architecture:

```text

Servers
Containers
Databases
      │
      ▼
Log Collection Layer
      │
      ▼
Central Log Platform
      │
      ▼
Search
Dashboards
Alerts
```

Benefits:

* Single Source of Truth
* Easier Troubleshooting
* Better Visibility
