# Logs

## Introduction

Logs are one of the most fundamental sources of information in software systems. Every application, service, operating system, database, network device, and cloud platform generates logs that describe what is happening internally.

Logs provide detailed records of events that occur within a system and are often the first source engineers examine when troubleshooting incidents.

In modern observability platforms, logs are considered one of the three pillars of observability alongside metrics and traces.

While metrics help answer:

> What is happening?

Logs help answer:

> What happened?

> Why did it happen?

> What error occurred?

> Which component failed?

Logs provide the detailed context required to investigate and resolve issues.

---

# What Are Logs?

A log is a time-stamped record of an event generated by a system, application, or service.

Examples include:

* User login events
* API requests
* Application errors
* Database queries
* Authentication failures
* Service startup events
* Deployment activities

Example:

```text id="1fkjq9"
2026-08-05 10:15:23

ERROR

PaymentService

Database connection timeout
```

Each log entry records information about a specific event.

---

# Why Logs Matter

Logs provide visibility into system behavior.

They help engineers:

* Troubleshoot incidents
* Investigate failures
* Perform root cause analysis
* Audit system activity
* Monitor security events
* Understand application behavior

Without logs, engineers may know a problem exists but have little information about why it occurred.

# Characteristics of a Log

A typical log entry contains:

### Timestamp

Indicates when the event occurred.

Example:

```text id="l0m2qy"

```

---

### Severity Level

Indicates importance.

Examples:

```text id="8z6m3k"

DEBUG

WARN

ERROR

FATAL
```

---

### Source

Identifies the component generating the log.

Example:

```text id="u2v8as"

```

---

### Message

Describes the event.

Example:

```text id="m5h1dn"

```

---

### Metadata

Additional context.

Example:

```text id="6r2wtk"

userId=789

environment=production
```

* API requests

* Validation failures

Examples:

* System startup
* Service failures

Generated by web servers.

Examples:

Generated by databases.

Examples:

## Security Logs

Generated by security systems.

Examples:

# Log Levels

Log levels help classify the importance of events.

## DEBUG

Used during development.

Contains detailed information.

Example:

```text id="6m1wfx"
Method entered:
processPayment()
```

---

## INFO

Normal operational events.

Example:

```text id="j3d2py"
Application Started Successfully
```

---

## WARN

Potential issues.

Example:

```text id="8x0rnb"
Disk utilization reached 80%
```

---

## ERROR

Failures that impact functionality.

Example:

```text id="k1v4mc"
Database Connection Failed
```

---

## FATAL / CRITICAL

Severe failures causing application shutdown.

Example:

```text id="d7n0wp"
Application terminated unexpectedly
```

---

# Structured vs Unstructured Logs

## Unstructured Logs

Plain text format.

Example:

```text id="6wzqja"
User login failed due to invalid password
```

Difficult to search and analyze at scale.

---

## Structured Logs

Stored using key-value pairs.

Example:

```json
{
  "timestamp":"2026-08-05T10:15:23Z",
  "level":"ERROR",
  "service":"payment-service",
  "message":"Database timeout"
}
```

Advantages:

* Easier searching
* Better filtering
* Improved analytics
* Machine-readable format

Modern observability platforms strongly prefer structured logging.

# Centralized Logging

Modern organizations collect logs from multiple systems into a central platform.

Benefits:

* Single source of truth
* Faster troubleshooting
* Improved search capabilities
* Better incident response

Popular platforms:

* Dynatrace
* Elasticsearch
* Kibana
* Splunk
* Grafana Loki

---

# Log Aggregation

Log aggregation combines logs from multiple systems into a centralized repository.

Example:

```text id="9m5rwe"
Application Logs

Database Logs

Container Logs

Cloud Logs

Security Logs
```

↓

```text id="4x2bvn"
Central Log Platform
```

This simplifies analysis and troubleshooting.

# Logs in Observability

Logs provide detailed context that metrics cannot.

Example:

Metric:

```text id="w8k2cs"
Error Rate = 15%
```

The metric identifies a problem.

Log:

```text id="3j0yqa"
Payment Gateway Timeout
```

The log explains the problem.

Metrics and logs work together.

---

# Logs and Root Cause Analysis

Consider an application outage.

Metrics show:

```text id="7q3rlt"
Response Time Increased

Error Rate Increased
```

Logs reveal:

```text id="2f8xdy"
Database Connection Pool Exhausted
```

This enables engineers to identify the root cause.

# Logs and Predictive Monitoring

Predictive Monitoring relies primarily on metrics.

However, logs provide supporting evidence.

Example:

Metrics indicate:

```text id="9v0mkf"

```

Logs reveal:

```text id="r6j4qa"

```

Together they help predict future failures.

# Logging Best Practices

## Use Structured Logging

Prefer JSON-based logs.

---

## Include Context

Always include:

* Request ID
* User ID
* Service Name
* Environment

---

## Use Appropriate Log Levels

Avoid logging everything as ERROR.

---

## Avoid Sensitive Data

Never log:

* Passwords
* Tokens
* Credit Card Information

---

## Centralize Logs

Store logs in a centralized platform.

---

# Common Logging Mistakes

## Excessive Logging

Produces unnecessary storage costs.

---

## Missing Context

Makes troubleshooting difficult.

---

## Inconsistent Formats

Complicates searching and analysis.

---

## Logging Sensitive Information

Creates security risks.

---

## Lack of Retention Policies

Can lead to excessive storage growth.
